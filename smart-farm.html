Project 02 · Smart Farm Case Study

센서 데이터를
확인과 대응의 흐름으로.

스마트팜 전문가 양성과정 조별 프로젝트에서 ICT 담당으로 참여했습니다.
DHT11 실측값의 대시보드 표시, 1시간 주기 Telegram 알림, LED 원격 ON/OFF 동작을 검증했습니다.

Live Demo ↗프로젝트 목록

웹 데모는 서비스 화면을 확인하기 위한 환경이며, DHT11·LED 실물 검증은 별도의 하드웨어 구성에서 진행했습니다.

01 · Overview

하나의 화면보다, 이어지는 운영 흐름을 만들었습니다

센서값을 읽는 데서 끝내지 않고 수집·전달·시각화·알림·제어까지 연결했습니다. 기능마다 실제 확인한 범위를 나누어 결과를 설명했습니다.

MONITOR

원격 상태 확인

DHT11 온도·습도와 마지막 수신 시각을 모바일 대시보드에서 확인합니다.

NOTICE

1시간 주기 알림

Node-RED가 저장한 최신값을 3,600초 간격으로 Telegram 메시지에 담아 전달합니다.

CONTROL

원격 명령

웹의 ON/OFF 명령을 MQTT와 시리얼을 거쳐 LED의 물리 반응으로 확인합니다.

02 · Problem & User

장치가 앞에 없어도 상태를 알고 대응할 수 있어야 했습니다

USER SCENARIO

원격으로 생육 환경 확인

운영자는 현장을 계속 지키지 않고도 휴대폰에서 온도·습도와 데이터가 마지막으로 들어온 시점을 확인합니다.

USER SCENARIO

필요한 순간에 명령 전달

운영자는 웹에서 ON/OFF를 선택하고, 명령이 장치까지 전달되어 실제 반응하는지 확인합니다.

핵심 질문

“지금 들어오는 값은 최신인가, 화면 밖에서도 상태를 알 수 있는가, 보낸 명령은 실제 장치까지 도달했는가?”

03 · Verified Cases

서로 다른 두 사용 시나리오를 독립적으로 검증했습니다

CASE 01

웹에서 LED 원격 ON/OFF

웹 명령이 통신 계층을 거쳐 물리 장치까지 도달하는지 확인했습니다.

검증 목적

웹 대시보드의 조작이 물리 장치의 동작까지 이어지는지 확인

사용자 시나리오

운영자가 장치와 떨어진 곳에서 ON/OFF 명령을 보내고 현장 반응을 확인

실제 수행

Arduino와 브레드보드에 LED를 연결하고 대시보드 버튼으로 명령 실행

제어 흐름

farm/pump의 ON/OFF를 PUMP_ON/PUMP_OFF 시리얼 명령으로 변환

검증 결과

웹 버튼 조작에 따라 실제 LED가 점등·소등되는 것을 직접 확인

구성

웹 대시보드 · MQTT · Node-RED · Arduino · 브레드보드 · LED

범위: LED 제어는 실물 검증했습니다. 같은 명령을 사용하는 실제 펌프 구동은 검증하지 않았습니다.

CASE 02

DHT11 모니터링과 1시간 주기 알림

실측값을 웹에서 확인하고, 화면을 열지 않아도 최근 상태를 받아볼 수 있게 했습니다.

검증 목적

재배 환경의 온도·습도를 원격 확인하고 화면 밖에서도 주기적으로 상태를 수신

사용자 시나리오

운영자가 대시보드에서 온습도를 확인하고, 접속하지 않은 상황에서도 Telegram으로 상태 정보를 확인

실제 수행

Raspberry Pi 5, Arduino, 브레드보드와 DHT11을 구성해 실측값을 Node-RED와 MQTT로 전달

데이터 흐름

시리얼 JSON을 온도·습도 토픽으로 분리하고 최신값을 저장해 3,600초마다 메시지 생성

검증 결과

실측 온도·습도의 대시보드 갱신과 Telegram 1시간 간격 메시지 수신 확인

구성

DHT11 · Arduino · Raspberry Pi 5 · Node-RED · MQTT · Web · Telegram

범위: 기능 동작을 확인한 프로젝트 검증입니다. 장기간 무중단 운영이나 센서 교정 정확도는 검증 범위에 포함하지 않았습니다.

04 · Data Flow

사용 경험과 실제 구현 구조를 단계별로 구분했습니다

USER FLOW

운영자가 경험하는 온습도 확인 흐름

DHT11 온습도 측정데이터 수집대시보드 표시1시간 주기 Telegram 메시지운영자 확인

대시보드 확인과 Telegram 수신은 같은 센서값을 활용하지만 서로 다른 전달 경로로 동작합니다.

05 · Functional Requirements

사용자가 확인해야 할 상태를 기능으로 구체화했습니다

FR-01연결 상태브로커 연결·실패·재연결 상태를 구분해 표시
FR-02실시간 센서온도·습도, 단위, 상태와 마지막 수신 시각 표시
FR-03변화 흐름최근 데이터를 그래프로 유지해 변화 방향 확인
FR-04원격 제어웹에서 ON/OFF 명령을 발행하고 장치 반응 확인
FR-051시간 주기 알림최신 센서값과 갱신 시각을 3,600초 간격으로 Telegram에 전달
FR-06모바일 접근HTTPS 환경에서 WSS로 연결하고 작은 화면에서도 주요 기능 사용

06 · Implementation

기능별 구현과 검증 범위를 구분했습니다

데이터 신선도정상 범위의 오래된 값을 현재값으로 오해하지 않도록 마지막 수신 시각을 함께 표시했습니다.
Node-RED 흐름 분리센서 수집, 최신값 저장, 1시간 주기 알림, 제어 명령 변환을 독립 노드로 나누어 오류 지점을 좁혔습니다.
보안 연결GitHub Pages에서는 WSS를 사용하고, MQTT·Telegram 인증정보는 공개용 흐름에서 모두 제거했습니다.
중계와 직접 연결Raspberry Pi 5·Node-RED 중계 경로와 Arduino의 HiveMQ Cloud 직접 연결을 각각 시험했습니다.
공개용 Node-RED 흐름 ↓ Node-RED 구성 설명

실제 프로젝트의 Node-RED 플로우를 기반으로 민감정보를 제거한 공개용 참고 자료입니다. 별도의 환경 설정 없이 즉시 실행되는 구성은 아닙니다.

장애 해결 기록 보기
  • UNO R4 WiFi가 5GHz에 연결되지 않아 2.4GHz SSID로 변경했습니다.
  • MQTT 연결 실패 시 WiFiSSLClient와 TLS 8883을 적용해 연결 경로를 수정했습니다.
  • 펌웨어 갱신 후 바뀐 USB 포트를 다시 선택해 업로드 오류를 해결했습니다.
  • Raspberry Pi의 무선 재연결과 사설 IP 변경 문제에 Tailscale 원격 경로를 사용했습니다.
  • HTTPS 페이지의 일반 WebSocket 차단 문제를 WSS 연결로 해결했습니다.
